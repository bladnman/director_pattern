# Director Pattern: for an agent

Use the canonical GitHub [package selector](https://github.com/bladnman/director_pattern/blob/main/pattern/README.md)
and [installation guide](https://github.com/bladnman/director_pattern/blob/main/pattern/INSTALL.md).
This website is a front door, not another installation contract. Reading it does
not authorize installation, updates, publication or migration.

The published release is [v1.1.0](https://github.com/bladnman/director_pattern/releases/tag/v1.1.0).
Current `main` also offers an unreleased flat-starter source candidate. Select the
actual package before copying files or applying its role and startup instructions:

- For a compatible new project, follow the [flat starter](https://github.com/bladnman/director_pattern/blob/main/pattern/starter/README.md)
  and its [manifest](https://github.com/bladnman/director_pattern/blob/main/pattern/starter/manifest.json).
- For a selected legacy v1 installation, follow [README-v1](https://github.com/bladnman/director_pattern/blob/main/pattern/README-v1.md),
  [INSTALL-v1](https://github.com/bladnman/director_pattern/blob/main/pattern/INSTALL-v1.md)
  and its [manifest](https://github.com/bladnman/director_pattern/blob/main/pattern/manifest.json).
- For an existing installation or canonical tracker, inspect its actual format,
  authority and adapters first. Follow the selector's preservation route; do not
  replace it with a different package or create a second tracker.

## Install request

The visitor copies this into the agent already working in the target project:

```text
Install the Director Pattern in this project: https://director.metal-sole.com
```

On that authorized request, continue directly with the canonical GitHub installation
protocol linked above. Do not send the user back to this website to repeat the same
request. Resolve published `main` to one exact reviewed commit and read the selected
package at that revision. Copy only the manifest-selected payload.

Preserve existing instructions, local adaptations, authority, specialist guards,
canonical trackers, unfinished work, exact sources and attachments. Follow the
selected package's privacy/version-control rules and the project's explicit choices.
Do not copy this website, maintainer material, repository metadata or private source
archives into the installation. An installer follows its actual assignment; it
need not already be a Director.

Use the selected package's role, startup, identity and recording instructions.
Do not add another package's manager, Recorder, roster or backend requirements.

## Verify an installation

```text
Verify the Director Pattern installation in this project. Check the loaded startup wiring, required files, configured mode, role index, Recorder route, and pinned source revision. Report any gaps and distinguish setup from current worker activity.
```

Follow the actual installed package's verification protocol and project guards.
Check role-index and Recorder requirements only where that installation uses them;
mark inapplicable checks as such rather than creating roles or reporting missing
prerequisites. The website cannot inspect the project or certify its setup.

Report actual reads, tool calls and returned evidence. Distinguish file/config
checks, fresh-host behavior, live execution, human acceptance and publication.
Keep required but unrun checks pending. A stored status or an actor label proves
neither execution nor accepted work. The checked 🎬 identity, actor labels and
**📋 SitRep** duties follow the selected canonical contracts, not this summary.

## Update an existing installation

```text
Update the Director Pattern in this project from https://director.metal-sole.com
```

Resolve the canonical source to an exact reviewed SHA and select the protocol for
its actual installed package:

- [Flat-starter updates](https://github.com/bladnman/director_pattern/blob/main/pattern/starter/payload/UPDATES.md).
- [Legacy v1 updates](https://github.com/bladnman/director_pattern/blob/main/pattern/engine/references/UPDATES.md).
- Unknown or conflicting formats: use the [installation selector](https://github.com/bladnman/director_pattern/blob/main/pattern/INSTALL.md)
  for reviewed preservation before changing files.

Back up and verify changed files. Compare installed baseline, current adaptations
and the pinned incoming revision. Preserve project authority, roles, adapters,
native state, exact sources, identities, privacy and unfinished commitments.
Use the selected protocol's affected checks and retain earlier evidence only where
it still applies. Record a new accepted revision only after its required checks
pass; partial or blocked work retains its actual gaps and prior accepted baseline.

Preserve daily discovery and notify/automatic/off preferences under that protocol.
Automatic updates require the project's explicit standing authorization and the
same safe comparison and verification. Do not reset throttles or invent a scheduler.
Do not migrate trackers, switch modes or replace project identity as an update side
effect. Publication and deployment remain separate authorized operations.
