Six slides

Ask for six onboarding slides. Capture the complete exact source and original attachments, identify each independently finishable outcome and plan substantive acceptance criteria. Assign the author with exact paths, a useful capability/effort choice and proportionate checks.

Midstream: “Keep participant instructions concise; put facilitator guidance in notes.” Capture that addendum before dependent work, reconcile the actual author, then legally requeue/revise, amend and replan the full scope with the same owner and observed handle. A state transition records replanning; it does not stop or restart the worker.

Submission enters review. Evaluate all obligations and declared human gates before acceptance. A deck-specific preference stays local. An explicit ongoing course-slide rule can be retained as a scoped canonical note without a reviewer gate.

Several independent outcomes

One message can ask for a folder, research, a repository and an app. Keep independently finishable obligations in linked requests sharing the exact source. If three are done and the fourth waits on an acknowledged external owner, recovery must preserve that truth. A grouping link is not a required-success dependency, and an acknowledgment is not source acceptance of the eventual result.

A growing UI project

Repeated UI work rediscovers accepted design principles. Maintain a design reference and UI role. If a later outcome spans UI, engine, art and independent testing, a bounded same-base Director may own detailed coordination while the Project Director keeps conversation, parent requirement trace and user-facing acceptance.

If that coordination recurs across outcomes, an authorized maintainer can implement an Experience header and its explicit task pointer. Preserve the testing role's independence and release/install authority. At closure, refresh stale selectors and canonical artifact pointers. The next relevant assignment must actually load the corrected knowledge.

Quality of life remains work

Keep fitting actor identities in progress and returns, proactively give the labeled SitRep while work is held, and record unknown model/effort facts honestly. Daily update discovery is due only in an active session after its rolling 24-hour interval; default notify does not authorize an update.

Safe updates use an exact published pin, verified backups, adaptation comparisons, schema/privacy checks and proportionate validation under the canonical pattern/starter/payload/UPDATES.md. No checking actor, offline daemon or automatic tracker migration is added.

The goal is full behavioral preservation with fewer compulsory actors—not simply the same names. Task counts and correction counts do not create departments or authority.
